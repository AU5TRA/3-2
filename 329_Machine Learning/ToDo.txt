Slide 9:

Principal Component Analysis (PCA)
The steps are:
1. Mean-center the data (subtract the mean of each feature from every data point).
This moves the data cloud to be centered at the origin.

2. Compute the covariance matrix Σ from the centered data.

3. Find the eigenvectors and eigenvalues of Σ.
Each eigenvector defines a direction (a "principal component"), and each
eigenvalue tells you how much variance is captured along that direction.

4. Rank the eigenvectors by their eigenvalues, from largest to smallest.
The eigenvector with the biggest eigenvalue points in the direction of greatest variance
— this is Principal Component 1 (PC1). The eigenvector with the second largest eigenvalue
is PC2, and so on.

5. Choose how many components to keep (call it k, where k < p).
You keep the top k eigenvectors — the k directions that capture the most variance.

6. Project the data onto those k eigenvectors. Each original high-dimensional data point
gets mapped to a new k-dimensional representation by computing its dot product with each
of the k eigenvectors.

0 is for greedy, and higher temp leads to higher random seletion
-Top k: Sampling selects the top k most likely tokens from the model's predicted distribution
-Top p: Sampling selects the top tokens whose cumilative probability doesnt exceed 

Prompting Techniques:
- General / zero shot:
It only provides a description of a task and some text for LLM to start with.
- One shot & few shot:
Provides n examples to the model so that can imitate the example and follow the pattern it needs to.
- System:
Sets the overall context and purpose for the LLM.
Defines its fundamental capabilities and purpose.
- Contextual:
Provides the specific details or background information relevant to the current task.
- Role:
Assigns a specific character or identity for the language model to adopt.
Frames the model's output style and voice. It adds a layer of specificity and personality.
- Step-back:
Improves the performance of the LLM output by first making it answer a general question related to the specific task.
This allows the LLM to allow relevant background knowledge and reasoning processes before attempting to solve the problem.
- Chain of thought:
Improves the performance of the LLM output by making it generate reasoning steps.
This helps the LLM generate more accurate answers and self-verify if the output is wrong by looking at reasoning steps.
Can be mixed with n-shot prompting.
- Self consistency:
Self consistency combines sampling and majority voting to generate diverse reasoning paths
and select the most consistent answers.
1. The LLM is provided with the same prompt multiple times. A high temp setting encourages divergence.
2. Extract answer from each response.
3. Select most common answer.
- Tree of thoughts:
It generalizes CoT as it allows to explore multiple different reasoning paths simultaneously.
- Reason and Act (ReAct):
ReAct enables LLMs to solve complex tasks with natural language reasoning combined with external tools.
- Automatic:
Prompt a model to generate more prompts.
Evaluate them.
Alter them.
Repeat.

Slide 14:
RAG:

LLMs store knowledge in their parameters learned from training data.
But this parametric knowledge has serious limitation:
- Knowledge cutoff: Training data has a fixed endpoint. ie trained in 2023, doesnt know about 2024
- Hallucinations: Generate plausible sounding false information with high confidence when lacking knowledge.
- No access to private data: Cant access a company's internal documents, db, or proprietary info.
- Costly updates: Retraining LLM to incorporate new knowledge requires enormous computational resources.

RAG solution:
Instead of answering purely from what it remembers, it queries
to an external knowledgebase at inference time. It retrieves
relevant information and generates response grounded in the retrieved context.

If query is too big it is chunked.

Loading: Import documents from various sources
Chunking: Break large documents into smaller pieces called chunks.
**This significantly impacts retrieval quality.
Embedding: Convert each chunk into a dense vector representation using an embedding model
Storing: Save these vectors in a vector database optimized for similarity search

The generator LLM receives the original query and retrieved context and
uses those to produce the final response.

**Use RAG when:

Knowledge changes frequently
You need factual accuracy with citations
Working with proprietary data
Budget is limited
You need transparency

**Consider fine tuning when:
Need to change model behavior
Domain specific reasoning is required
Knowledge is stable
Speed is critical

GNN

For GNN, to create embeddings we do a simple process.
-First aggregate neighbors for N hops, (1 hop in the simplest case)
Aggregation has to be indifferent to number nodes or order, so it is usually an
aggregate function like sum, max, mean, etc
-Then update current node's embedding based on this aggregation.
Aggregation is passed through weights W_k and update is passed through weights B_k
** All nodes share the same update and aggregate weights.

CNN is a special case of GNN where the neighbors are the neighboring pixels.
Transformers are GNNs where the graph is fully connected with positional encoding.
